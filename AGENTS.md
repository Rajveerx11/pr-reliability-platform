# Repository working rules

1. Keep product plans in `plan/`.
2. Keep documentation in `docs/`. Root `README.md` only links to key files.
3. Put feature code inside its owning `apps/`, `workers/`, or `packages/` folder.
4. Track each feature with one GitHub issue before implementation.
5. Link each pull request to its issue and relevant decision in `plan/v1.md`.
6. Update `Changes.md` whenever tracked files change.
7. Keep files focused and medium-sized. Split files when they mix responsibilities.
8. Use simple English in plans, documentation, issue text, and comments.
9. Add tests beside each code area. Do not merge when required checks fail.
10. Never publish comments, patches, or commits without explicit human approval.
